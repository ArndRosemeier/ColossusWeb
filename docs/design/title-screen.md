# Title screen — full-width campaign workbench

Owner: “Ok, works. Please take a look at the title screen. I would like for that to also use the full width and also make it a lot more interesting. Right now its pretty basic and bad design.”

COPIES: 1 — checked, no duplication (grepped: SetupScreen, VARIANT_META, cappedRows, onVariantChange, LobbyPanel); SetupScreen remains the single setup controller.

The old layout capped the entire page at 52rem, stacked the lobby before local setup, and used an oversized SVG wordmark above a small heading. Independent dispatcher baseline measured an 832px setup at both 1440 and 1920 and 15px horizontal overflow at 360. This slice replaces the presentation with a full-width illustrated title and a usable setup workbench in **both** Classic and Animated modes.

The shell uses `clamp(20px, 2.8vw, 56px)` gutters with no content max-width: at 1920 the main content uses about 94.4% of the viewport. The top navigation carries a compact Colossus wordmark, existing What's new control and cued identity. A 430–500px desktop hero puts live HTML text over the illustration's quiet left half; mobile crops toward the dragon/tower on the right with a stronger dark gradient. Both action links are ordinary anchors to actual `#local-setup` / `#online-lobby` sections, whose negative tabindex also permits native keyboard target focus. The art remains decorative, with an empty alt and a dark fallback background so its availability does not determine text contrast.

A saved campaign appears directly below the hero with actual variant/player/turn/phase/save-time metadata and the original Load saved game callback. Below, a 1.4:1 desktop workbench gives the local campaign form more space beside the existing lobby. It becomes one column below 1180px. Commander fieldsets retain all original inputs, options, marker previews, remove/add behavior and payload; below 700px they use an explicit labeled grid with a full name row and paired control/personality/color/action rows. The minimum two and variant caps three/six/nine are unchanged. Appearance moves into native details with the same preference selectors. There are no tabs, hidden lobby states or animation assets to wait for.

`SetupScreen` is still the single controller: `VARIANT_META`, `cappedRows`, add/remove, variant truncation and the exact onStart mapping are retained. The actual `LobbyPanel` stays mounted across edits/anchors/appearance changes; no lobby, session, network, game engine, serializer or application command path changed. A focused test uses the existing FakeHubServer and real HubSession to prove a single connection persists and online creation still receives the selected variant/cap. It never opens a live test room.

Layout lives in separately imported `web/src/components/setup.css` with setup-only selectors. Obsolete `.setup`/`.hero`/`.brand-svg`/`.lede`/`.player-row` rules and the old hero version margin are retired from index.css. Shared legacy `.setup-panel`, lobby and button declarations remain, including in-game button/focus values; `.brand-inline` is unchanged. The new setup scopes override legacy lobby sizing/animation only while it is inside `.setup`. No body/html/font-root, board, overlay or dialog styling is changed. This redesign adds no ambient animation, and it loads no creature sprite atlases on the title screen.
