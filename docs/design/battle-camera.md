# Animated encounter camera

Owner: “one more animation. The moment a battle starts ... main board zoom and turn into that hex, then becoming the battle land. And a zoom out at the end again.”

COPIES: 1 — checked, no duplication (App.putState, local/remote commit setters and visible battle branches); one useBattleCamera observer carries every visible boundary.

## One boundary, immediate game state

`useBattleCamera` observes old/new GameState at the top of App.putState, before the outgoing DOM disappears. The setter still immediately updates stateRef and React state; both createCommitPath.local and remote adoption use it unchanged. No battle command, delayed commit, second game store or input-authority rule was added. App only adds a board-pane ref and a replacement flag at explicit start/load/online entry calls; null also cancels. All original controls, ownership and keyboard paths remain authoritative during the decorative transition.

`battleCameraBoundary` compares actual visibility (`battle && !done`), not commands or battle turns. The encounter hex comes from attacker/defender legion IDs; exit reads the previous legions first, so an eliminated loser or final winner state still returns to the correct location. Same-battle moves/strikes/turns/duplicate snapshots never replay. Replacing the active encounter without a painted main board cancels. Direct active-battle load has no zoom source. Fully coalesced/instant AI encounters that never paint have no fabricated transition.

## Camera and compositing

The outgoing actual SVG is captured before commit; a layout effect captures the newly mounted incoming actual SVG. `battleCameraFocus` maps the measured hex center onto the other board's center after a seven-degree turn and bounded1..14× zoom. Translation explicitly accounts for rotation and measured screen offsets, including scrolled coordinates. One820ms Web Animations timeline zooms/turns/crossfades; entry reveals the battle SVG and exit reverses from it into the updated main board at that same hex. There is no rasterized HTML, generated transition art, new URL or per-frame JavaScript.

Native labels, gates and markers would become huge as the hex approaches. Independent WIP screenshot review identified that distraction. The main snapshot therefore has one additional quiet scene copy with those annotations removed; ONE native opacity animation dissolves the annotated copy early on entry and restores it late on exit. Selected standing-legion groups are tagged only in the clone and removed whole, including their outer selection frame. Both copies use already-loaded landscape artwork and independent SVG ID namespaces. This avoids hundreds of separate annotation timelines and leaves the real board entirely untouched. CSS animations/transitions in snapshot descendants are frozen; existing creature HTML style/frame and existing canvas bitmaps are preserved, not replayed. The camera snapshots are temporary revealed presentation, never an alternate board renderer or source of hidden information.

Snapshots copy only SVG content, not metadata/control panels or decision dialogs. Native control nodes, event attributes, tabindex and interactive data targets are stripped; SVG IDs and local URL/href references are namespaced with a React-scoped capture ID. Existing canvas bitmap pixels are copied with drawImage because cloneNode alone would blank unsupported creature chits; no DOM-to-image conversion/readback occurs. The root is inert, aria-hidden, pointerEvents none, fixed to the board pane's visible viewport intersection and clipped. It covers no toolbar/sidebar. The underlying real board is already mounted and interactive; there is no animation-specific command blocker.

Reduced motion keeps the modern art and uses one150ms outgoing-opacity fade without transform or quiet-scene duplication. Classic performs no capture/overlay. Live uncheck or reduced-motion changes cancel immediately rather than replay. Resize, nested/window scroll, visualViewport changes, replacement, null, supersession and teardown cancel all native animations and remove the overlay/listeners. Finished overlays also clear the cleanup ref so snapshots are released. There are no animation RAFs, timers or observers left running.

Unexpected geometry/copy/animation failures clean up and queue one message through existing App.notify after the immediate game commit (avoids recursive setter calls). The engine's win/draw guard refuses even notice commands after game over, which would have hidden an exit-camera failure. App's same local-only notify reducer now updates only the existing message field for a finished game; no rule command, network publication or save format changes. A real Chrome forced exit-animation failure after a two-player Titan elimination proves the won state still matches the engine except for that intentional local error sentence. A hidden/unlaid-out source, offscreen pane, direct load or superseded board that never painted legitimately skips the camera. Required game state is never replaced by placeholder data.
